# 카카오 사진 수신과 메시지 연결 검증 — 2026-11-18 UTC

## 판정

**사진은 정상 수신됐지만, 사진 파일 → 원본 말풍선 → CSV 행의 연결은 미확정이다.**
운영 수집 검증은 `cf5c5806`에서 관리자가 열어 준 세션의 한 방에 한정했다. 화면에서 직접
내보내기와 내려받기를 실행했으며 무인 수집 완료 증거가 아니다. 메시지 전송·설정 변경,
미확정 사진의 학생 질문 연결, 정본 수락 또는 PDF 발행은 하지 않았다.

| 확인 단계 | 실제 운영 관측 | 판정 |
| --- | --- | --- |
| CSV 수신 | 8,648 bytes, 데이터 48행. SHA-256과 크기가 수신 기록에 일치 | 수신 확인 |
| 사진 수신 | 294,841 bytes. SHA-256과 크기가 수신 기록에 일치 | 수신 확인 |
| 방 확인 | CSV와 사진의 화면 기록에 같은 방 경로. 두 기록 각각에 같은 방의 유효한 사진 링크 6개 | 방 범위만 확인 |
| 사진 파일 → 원본 말풍선 | 사진 수신 관측의 `target.kind=UNAVAILABLE`, 대상 경로 없음 | 이 단계에서 막힘 |
| 말풍선 → CSV 행 | CSV에 값이 `사진`인 행 7개. 특정 링크가 없어서 이 파일의 행 정합을 시작할 수 없음 | 미확정 |

수신 화면마다 메시지 영역 41개가 관측됐다. CSV 행 수, 화면에 로드된 사진 링크 수,
`사진` 문자열이 나타난 행 수는 서로 다른 값이다. 그 차이만으로 누락·앨범 수·전체 범위를
확정할 수 없다. 증거는 보호된 수신 기록에 보존하며 학생 정보, 대화, 사진, 실제 식별자와
다운로드 주소는 이 문서에 넣지 않는다.

## 확인된 실패 지점과 아직 모르는 원인

1. [MANUAL 수집기](../../services/kakao_archive_collector/eom_kakao_archive_collector/manual_download.py#L123)는
   같은 브라우저 페이지의 `request`와 `download` 이벤트를 기록한다. 직접 확인된 카카오 사진
   경로가 없으면 [요청 연결기](../../services/kakao_archive_collector/eom_kakao_archive_collector/download_origins.py#L148)가
   같은 페이지에서 유일하게 연결된 GET·리디렉션 기록으로 원래 경로를 확인한다. `UNAVAILABLE`은
   파일이 없다는 뜻이 아니라 **파일을 어느 사진 요청에서 받은 건지 검증하지 못했다는 뜻**이다.
2. 당시의 수신 기록은 연결 결과만 남겼다. 원래 GET 이벤트가 없었는지, 브라우저가 다른
   페이지에 기록했는지, 중간 리디렉션이 누락됐는지는 확정할 수 없다. 별도 브라우저 창이
   실제로 열린 것은 별개의 확인 사항이며, 출처 누락의 직접 원인이라고 단정하지 않는다.
3. [행 정합](../../services/catalog_service/eom_catalog_service/kakao_photo_alignment.py#L142)은
   수신된 사진의 이 경로를 먼저 요구한다. 그 경로가 방 안의 말풍선 하나와 일치하는지 본 뒤,
   양옆의 완전한 문장과 중간 메시지 순서가 CSV에서 딱 한 곳에 맞을 때만 행을 제안한다.
   이번엔 첫 조건에서 거부됐다. 행 정합을 시도한 결과 여러 행에 매치됐다는 뜻은 아니다.
   같은 방이라는 사실이나 파일명·크기·시간 근접성으로 행을 임의 선택하지 않는다.

## 반영 범위와 다음 검증

- 후속 수집기 `44b643e2`는 운영에 반영했고, 아래와 같이 실제 한 방을 재검증했다.
  MANUAL에서 출처가 미확정이면 해당 수신 폴더에
  `origin-diagnostic.txt`를 한 번만 남긴다. `REDIRECT_PREDECESSOR_MISSING`,
  `FINAL_URL_OBSERVED_ON_OTHER_PAGE`, `FINAL_URL_AMBIGUOUS`, `REQUEST_EXPIRED` 등
  고정 사유와 일치 여부만 기록하며, 같은 주소라도 다른 페이지의 요청을 채택하지 않는다.
  코드가 기록할 수 있는 것은 관측 여부이지 SDK에서 이벤트가 아예 발생하지 않았다는 증명이
  아니다. 당시 파일에 사유를 소급 기록하지 않는다. 기존 수신 성공·정합 기준은 그대로다.
- `bcca533c`는 목록에서 연 별도 대화창을 검증하는 수정이며 `44b643e2` wheel에 포함됐다.
  격리 Chromium에서 맞는 창의 수집 및 다른 방의 창 거부를 확인했다. 실제 사진 출처
  누락을 해결했다는 증거는 아니다. 전체 방·예약 수집은 꺼져 있다.
- 다음 작업은 원래 사진 링크의 식별자를 실제 최종 전송과 연결할 수 있는 검증 가능한 경로를
  찾는 것이다. 같은 창이라는 이유만으로 직접 다운로드 주소를 말풍선에 연결하지 않는다.
- 같은 방·유일한 말풍선·유일한 CSV 행의 연결을 새 수신으로 검증한 뒤에만 정상 연결로
  처리한다. 그 뒤에도 학생 구분과 실제 발신 역할·기간 기준을 확인하고, Studio에서 학생별
  PDF를 열고 다운로드하기까지 확인해야 실제 한 방 검증이 완료된다.

## 후속 실방 재검증 — 최초 사진 요청 연결 누락 확인

새 MANUAL 세션 하나로 이전과 같은 방에서 사진 1개와 CSV 1개를 각각 한 번 받았다.
둘 다 `RECEIVED`이며 이전 수신과도 개별 SHA-256이 같았다. 사진 294,841 bytes, CSV 8,648
bytes·48행, 화면 관측은 메시지 영역 41개, CSV의 `사진` 표시는 7행이다. 그 수치로
메시지 연결이나 방 전체 수집을 판단하지 않는다. 메시지 전송·설정 변경은 없었다.

```text
code=INITIAL_PHOTO_REQUEST_NOT_OBSERVED
candidates=0 source_get=NOT_CONFIRMED final_same_page=1 final_other_page=0 receipt=RECEIVED
```

최종 다운로드 주소와 일치하는 허용 주소 요청은 같은 페이지에서 관측됐다. 하지만 해당 요청의
SDK `redirected_from`이 없었고, 관측된 요청 자체도 원래 카카오 사진 경로가 아니었다. 그래서
이 다운로드에 대해 원래 사진 GET부터 시작하는 유효한 연결이 하나도 없었다. **최종 주소를
관측하지 못했거나 CSV 정합에 실패한 경우가 아니다.** 해당 요청이 전달된 원인(예: 앱의
직접 요청, 화면의 스크립트 처리)이나 별도로 먼저 실행됐을 수 있는 브라우저 내부 동작은 이
진단만으로 단정하지 않는다.

격리 Chromium에서 DOM에는 카카오 사진 링크가 있지만 실제 다운로드는 직접 CDN으로 가는
모양을 재현했다. MANUAL에서는 실방과 같은 코드로 수신 파일을 보존하고 미확정으로 남겼다.
자동 수집에서도 해당 시나리오를 연결된 사진으로 수락하지 않았으며, 현재 안전 중단 경로는
그 시도에서 다음 CSV 내보내기를 시작하지 않는다. 이는 합성 확인이며 실제 AUTO 수집 증거가
아니다. 이번 실방의 말풍선·CSV 행 정합, 정본 원본 등록과 학생 PDF는 아직 실행하지 않았다.

## 다음 실방에서 확인할 화면 주소 근거

운영 세션은 종료됐다. 기존 수신 관측은 원래 카카오 다운로드 버튼 경로는 남기지만, 외부
이미지 주소를 남기지 않아 과거 수신을 가지고 정확한 주소 대응을 다시 계산할 수 없다.

새 진단은 `INITIAL_PHOTO_REQUEST_NOT_OBSERVED`인 수동 수신에서, 같은 방의 원래 다운로드
버튼이 붙은 사진 카드만 대상으로 **사진 링크와 실제 표시 이미지 주소**를 최종 다운로드
주소와 정확히 대조한다. 브라우저 밖에는 일치 속성의 종류, 없음·복수·관측 불가 값만
별도 진단에 기록한다. 주소, 쿼리, 해시, 메시지 식별자나 화면 텍스트는 나오지 않는다.
사진 파일의 보존과 기존 출처 판정은 그대로이며, 일치가 하나여도 질문에 연결하지 않는다.

격리 Chromium에서 사진 링크 일치, 표시 이미지 일치, 쿼리만 다른 경우의 거부, 여러 카드의
동일한 주소 및 자료 미확정 보존을 확인했다. `8e819752` 수집기를 운영에 반영했지만
실방이 일치하는지는 아직 모른다. 다음
실방에서 일치하면 해당 속성과 사진 식별자의 의미를 검증하고, 일치하지 않으면 클릭 전후의
요청·응답 중 주소를 선택하는 경로를 추적한다. 어느 경우에도 이 검사만으로 자동 연결을
허용하지 않는다.
