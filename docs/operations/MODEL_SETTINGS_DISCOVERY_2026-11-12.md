# 모델 설정의 상태 확인과 선택지 표시

## 원인

2026-11-12 운영 read-only 조회에서 계정 native 목록은 8개 모델을 제공했으나,
문항 제작의 공식 model-options는 `gpt-5.6-terra`의 `high`/`xhigh`만 반환했다.
슬롯별 실제 검증 정책의 범위 때문이며, 프리셋 편집기가 모델명을 Terra로 하드코딩해서
필터링한 것은 아니다. 상태 관측은 계정의 목록을 갱신하지만 검증 정책을 확대하지 않는다.
또 화면에서 이미 읽은 선택지는 다른 화면의 OBSERVE 이후 자동 재조회되지 않았다.

## 변경 범위

- 모델 설정 안에서 상태 확인 후 같은 설정의 model-options를 다시 조회한다.
- 실행 관리와 모델 설정은 공식 OBSERVE의 진행 중 요청과 멱등 재전송 코드를 공유한다.
- 모델/추론 깊이를 버튼으로 펼친다. 선택된 값과 비활성 사유를 구분한다.
- native 목록에만 있는 모델은 `실행 검증 필요`, 기존 실행 계약에 없는 깊이는
  `현재 실행 규약 미지원`으로 표시한다. 선택·발행은 기존 검증된 조합만 허용한다.
- 선택 편집은 새로고침 후 유지하고, 철회된 선택은 임의 다른 모델로 대체하지 않는다.
- 새 모델 추론/로그인/정책 변경/DB migration은 없다. 새 모델의 사용 가능성을
  검증한 작업으로 이 UI 수정을 해석하면 안 된다.

## 검증 및 배포 경계

실제 Chromium에서 선택·초안·검증·발행의 합성 경로, 상태 갱신, 중복 클릭,
늦은 응답, 로그아웃, 320/390px 화면을 확인한다. 실제 운영 모델을 호출하지 않는다.
OBSERVE HTTP 응답을 잃거나 대기 시간을 넘긴 경우 같은 키/명령을 이어서 조회하는
Node 회귀 검사와 기존 API/BFF/권한/패키지 검사도 수행한다.

Web-only 배포를 사용한다. API/platform/QUERY/INDEX/문항 worker의 설치본과 정책은
바꾸지 않는다. 배포 후 HTTPS 정적 자산과 설치 RECORD를 대조하며 실제 관리자
화면의 상태 확인 성공과 새 모델 실행 검증은 별도 결과로 기록한다.

첫 전체 Web 검사에서 오래된 계정 화면 browser fixture가 제거된 `presetRoleLabel`
함수를 source 절단 경계로 사용해 실패했다. 실제 `workerSlotLabel` 경계로 수정했으며
운영 계정 기능은 변경하지 않았다. 최초 실패 로그는 staging에 보존한다.

소스 검증: Web suite **534 PASS**(옵트인 Chromium 포함), 별도 집중/문맥 검사
25 PASS, 변경 Python의 Ruff/format 및 release-integrity mypy PASS.
기존 Starlette/httpx deprecation warning은 검증 실패가 아니다.
