# CUDA installation capture for the finite benchmark controller

Design before implementation, 2026-10-18 UTC. Extends the existing
[finite root series](EMBEDDING_BENCHMARK_SERIES_CONTROL.md), not its authority.

1. Responsibility: compose the installed root controller with the same protected
   CUDA receipt, prefix inventory, host/library descriptors and resource-file
   observations as the native reader. Never start a native interpreter as root.
2. Canonical sources are independently selected configuration/receipt pins and
   their existing protected files. File paths are locations, not new identities.
3. Preserve configuration ID/revision/semantic hash/raw hash, receipt raw hash,
   inventory, proof, bundle and base/CUDA host snapshot closure. No schema change.
4. Extract the existing owner-neutral file capture by composition. Native admission
   retains its mandatory native-interpreter guard at construction, use and close.
   Root composition separately requires actual root identity. No bypass flag or
   subclass that disables a guard, and no new source or numerical permission.
5. Access is a bounded set of fixed-path reads, one immutable inventory and held
   file descriptors. Parse/hash once; recheck existing epochs and current boot,
   account/group, GPU identity and exact read-only namespace mount on continuation.
6. Cost is O(n) capture/recheck in the existing prefix inventory size, O(n) metadata
   and O(k) held host/resource FDs. No new DB/index/cache/queue or binary copies.
7. The finite context owns host/resource descriptor cleanup, including constructor,
   body and final-fence failure. No physical GPU flock is acquired by this reader.
   The existing root driver still owns original unit/resource lifetime evidence.
8. The caller must already run in the independently prepared protected loader-cache
   namespace and valid working directory. Capture verifies the actual mount; it
   never creates a mount, mutates global loader configuration or invents a witness.
9. Infrastructure composes public file-capture behavior and the existing finite
   root series. No worker/DB/NAS/API access, credential capture, login or auth renewal.
10. A stale/missing/mismatched installation fails explicitly, without latest,
    model retry, prefix replacement or a new execution identity. Cleanup uncertainty
    remains an error; the original evidence is not rewritten as success.
11. Copying the native capture into a root helper is superficially smaller but
    creates two receipt/host/resource rules. Instantiating native admission as root
    or making its interpreter guard optional would weaken the existing boundary.

Source composition is not installed operator/namespace acceptance, actual source
admission, six numerical runs, comparative performance or device-default approval.
Existing numerical prefixes, units, selectors, CPU default and C1–C5 remain intact.

## Implemented source boundary

`ProtectedCudaInstallationFiles` owns the unchanged CUDA2.0/2.1 protected receipt,
inventory/config/proof/bundle/host closure and held host/resource descriptors.
It exposes observations, not the keyword-shaped native admission protocol and not
physical ownership. The existing native class composes it, enforcing its exact
native interpreter before any reads, after construction, on use and on close.
The CPU reader and numerical encoder/codec implementations are unchanged.

`capture_root_benchmark_cuda_runtime` separately requires actual root and explicit
backend pins, retains the shared capture for the whole finite context, and checks
root/current installation on exit. `serve_installed_root_benchmark_series` is a
small composition of that scope with the existing six-launch controller. No new
listener, source reader, execution journal, model entry or retry path is introduced.

Six failing interruption tests reproduced a descriptor-retention problem during
construction/context entry. Those ownership transitions now clean up even on
KeyboardInterrupt, while propagating cancellation instead of swallowing it.
All six targeted tests then passed. Constructor cleanup uncertainty remains its
own error rather than being collapsed into a generic capture failure.

Initial development also caught use of the wrong configuration attribute name:
the existing model has `config_sha256`, not `configuration_sha256`. The first
CUDA reader run was25 FAIL/21 PASS; using the actual contract field restored46
PASS, without a schema alias or weaker hash check. A nonexistent optional test
path was corrected before any tests ran. These are development failures, not live
runtime incidents. Earlier119 and695 passing cohorts overlap; do not sum them.

Positive root/current-installation and device inputs in these source tests are
synthetic; actual nonroot denial and no-ML-import subprocess checks are genuine
negative/import evidence. No actual mount/controller/model/physical-lease test,
DB mutation, numerical-prefix replacement, user login or activation is implied.
An installed operator must still provide the actual reviewed private loader-cache
namespace/working directory. This source does not fabricate or create that mount.
