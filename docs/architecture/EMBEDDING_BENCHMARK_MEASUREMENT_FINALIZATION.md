# Original benchmark measurement finalization

2026-10-18 UTC. Design before behavior. Reuse released benchmark1.0 and existing
Artifact/state protocols; no schema, dependency, runtime, authentication or device
default changes. A complete measurement is not GPU activation approval.

1. Responsibility: Catalog resolves the original six canonical launch receipts,
   native/root records, numerical and timing evidence. The Orchestrator alone
   stages/commits the original benchmark Job's preallocated Artifact and finishes
   VALIDATING_RESULT→COMMITTING→SUCCEEDED. No child benchmark Job is created.
2. Canonical source is the exact original owner request, registered input/policy,
   six immutable launch Artifacts and CPU1's pre-CUDA f64 reference. Existing
   Catalog admission rechecks actual ADMIN/session/source/Graph/policy at each
   short database root, including replay; no receipt is an authentication grant.
3. Preserve benchmark/Job/execution/Artifact/revision, semantic and raw hashes.
   Final result uses the original Job's Artifact/revision, never another identity
   on crash, failure or replay. Original launch f32/witness bytes remain referenced.
4. Resolve canonical `launch-receipt.json`, resources, root preparation/completion,
   token and binary pointers with exact producer/schema/media/approval/hash checks.
   Missing legacy receipt members fail explicitly; never manufacture pointers.
   All six fixed ordinals, original controller/source pins and associations match.
5. Access is indexed original Job/event lookup, six-launch ordered iteration and
   bounded member maps. Fixed member tuples and sets prevent duplicates; no queue,
   registry, source scan, global cache or new index is introduced.
6. Complexity is existing bounded numerical assessment plus O(six launch metadata
   and final JSON/f64 bytes). Final vector evidence points to original f32 members;
   source files, PNGs, vectors and complete worker outputs are not recopied.
7. One original-Job publication lock serializes local staging and NAS commit.
   Short row-locked/source-fenced roots seal the exact manifest/hash intent and
   final DB records; no transaction spans inference or NAS commit. Local lock
   files are coordination only, not canonical state or authority.
   A required typed Catalog source validator runs in the final caller's same
   COMMITTING transaction before Artifact records or SUCCEEDED. It reuses the
   replay closure for original reference/token/f32/timing/root/resource members,
   without rerunning the numerical assessor; sealed staging alone is insufficient.
8. Catalog infrastructure owns supplied-value assessment and authorized reads;
   Orchestrator application owns publication/state. Reuse existing source/journal
   contracts, not a new optional trust-caller evidence port or publication framework.
9. Nine gate states describe only proven facts. Source/runtime/numerical/timing/
   resources/cleanup use actual canonical receipts. Standalone sandbox/image
   regression proof not materialized here is NOT_RUN, never an inferred PASS.
   MEASURED records completed actual comparisons even if CUDA loses a performance
   or numerical gate. CPU remains selected; all activation gates remain separate.
10. Exact SUCCEEDED replay reads/revalidates the committed result without another
    numerical run, Artifact, event or identity. COMMITTING resumes its sealed
    staged file set and intent, including NAS-committed/DB-uncommitted recovery;
    changed/missing bytes or late revocation fail closed without overwrite/retry.
    An original external member missing during recovery leaves COMMITTING and no
    approved result revision. The post-publication/replay check remains required.
11. A generic control-file publisher is simpler but creates a different Job and
    bypasses the original benchmark state/identity. Requiring all activation
    gates before retaining a valid slower-CUDA measurement would also force
    unnecessary training. The original measurement owner is the smaller boundary.

New operating-proof schemas are deferred until actual measured CUDA superiority
makes activation relevant. A NOT_RUN-only synthetic benchmark is not publishable:
this path requires all six actual COMPLETED, cleanup-confirmed canonical launches,
complete numerical/timing assessment and every prescribed repetition.

Tests use explicit synthetic source/auth/runtime and local filesystem/SQLite
fixtures. They are source evidence, not actual authentication, PostgreSQL locking,
six model runs, GPU eligibility or device-default acceptance.
