# 기출변형에서 유사도 활용 제안

상태: 설계 제안. 현재 기출변형 또는 유사도 운영 활성화를 변경하지 않는다.

## 목적과 경계

기출변형의 출발점은 사용자가 고른 **기출 문항 Revision 한 개**다. 이 문항의
원본·풀이보고서·Graph 근거를 고정하는 기존 `past-exam-variation-request/1.0`과
`PAST_EXAM_VARIANT_OF` 관계는 그대로 둔다. 유사도는 원본을 고르는 데 도움을 주고
완성된 변형이 단순 복제인지 검토하는 보조 신호다. 검색된 다른 문항을 Evidence Bundle에
몰래 넣거나, 한 문항의 1:1 변형을 다중 원본 변형으로 바꾸지 않는다.

## 제안하는 사용 흐름

1. 사용자가 기출 원본을 고를 때, 기존 로컬 임베딩 QUERY로 관련 문항 후보를 제한된
   개수만 제시한다. `CONTENT`, `CONCRETE`, `METADATA` 결과를 별도 의미로 표시하고,
   수치 점수를 ‘풀이가 몇 % 같다’로 설명하지 않는다. 후보를 연 뒤 실제 원문·풀이보고서와
   Graph 근거를 확인하고 사용자가 최종 원본 한 개를 선택한다.
2. 출제 요청은 그 원본 Revision과 변형 축을 고정해 현재 1:1 Workflow로 보낸다.
   유사도 후보 목록 자체는 출제 근거가 아니다. 기존 출제·검토의 과학 정확성,
   근거 연결, 독창성, 최대 3교정 경계가 계속 권위자다.
3. 초안이 나온 뒤 원본과 가까운 후보를 비교 자료로 제공한다. 검토자는 ‘핵심 착상은
   전이되지만 조건·표현·판단 경로가 달라졌는지’와 ‘숫자·말만 바꿨는지’를 구분한다.
   단순 벡터 점수로 승인·차단하지 않는다. 등록 전 초안을 직접 조회·임베딩하는 계약은
   현재 승인된 Item Revision 조회와 다르므로, 이 단계는 별도 successor 계약과
   권한·보존 정책을 설계한 후 구현한다. 그전에는 기존 승인 문항에 한정해 회귀 평가한다.

## 데이터·권한·성능 계약

- 정본은 Catalog의 Item/분석 Revision, Graph snapshot, source 위치와 해시다. 임베딩
  인덱스와 유사도 결과는 재생성 가능한 파생물이다. 요청과 비교 기록은 사용자,
  원본·후보 Revision, Graph/정책/인덱스 버전, 모델·쿼리 계약을 명시적으로 고정한다.
- Studio → Application API → 기존 Orchestrator/Catalog 조회 경계를 사용한다. 현재
  행위자의 권한을 각 조회에서 재확인하며 worker가 DB·NAS·QUERY에 직접 접근하지 않는다.
  권한 없는 후보·만료된 포인터·해시 불일치는 노출하지 않고 명시적 오류로 처리한다.
- 주요 접근 패턴은 Revision 키 조회, 상위 `k`개의 순서 보존, Revision 집합 중복 제거,
  선택한 후보의 Graph 이웃 탐색이다. 기존 인덱스와 맵/집합을 재사용하며, 새 테이블이나
  벡터 저장소를 전제하지 않는다. `k`와 Graph 확장 폭을 제한하면 결과 조합은 O(k),
  후보별 정본 조회는 기존 색인 키 조회다. 520개보다 커지는 corpus에서도 전체 문항을
  UI 요청마다 순회하거나 본문을 서비스 사이에 대량 복사하지 않는다.
- QUERY는 원래 요청의 멱등 키·claim·lease를 사용하고 재전송 때 새 검색을 만들지 않는다.
  검색 불가 시 원본 고정 출제는 독립적으로 가능하지만, 비교를 수행하지 못했다는 사실을
  표시한다. 유사도 실패를 근거 검토 PASS로 해석하거나 최신 인덱스로 몰래 대체하지 않는다.

## 구현 순서와 검증 기준

1. 현재 설치된 QUERY·권한·Graph/분석 pin과 실제 상위 후보의 품질을 확인한다. 원본
   Revision 정확 일치, 다른 사용자 권한, 모델/인덱스 교체 시 재현성을 회귀 검증한다.
2. 기존 조회 use case 위에 **읽기 전용** 후보 화면을 만든다. 선택한 원본은 한 개만
   유지하고, 후보는 설명 가능한 정본 연결을 거친 후 보여 준다. 빈 결과·시간 초과도
   사용자에게 구분해 알린다.
3. 원본 대비 복제 위험을 검토자가 판단하도록 비교 화면과 근거를 연결한다. 초안 조회가
   필요하면 먼저 JSON Schema 2020-12와 Pydantic successor를 정의하고, Orchestrator의
   공식 경계에서만 처리한다. 점수 임계값 하나로 자동 승인하는 방식은 채택하지 않는다.
4. 여러 원본과 변형 결과의 사람이 이해할 수 있는 사례를 평가해 후보 제시가 실제
   선택·검토 시간을 줄이는지 확인한다. 교육 품질과 정답 유일성은 별도 검토 기준이다.

가장 단순한 대안은 임베딩 점수만 프롬프트에 붙이는 것이다. 하지만 그 방법은 원본 한 개
고정, 권한, Graph 근거, 복제와 착상 전이의 차이를 보장하지 못하므로 채택하지 않는다.
