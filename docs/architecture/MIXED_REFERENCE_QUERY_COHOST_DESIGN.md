# Mixed reference QUERY cohost

2026-10-19 UTC. Required activation boundary for mixed review candidates, not a new
chat feature or a new numerical service.

1. **Responsibility:** the installed reference QUERY supervisor keeps its existing
   reference1/private1 runtime. An explicitly selected optional mixed reference2
   runtime serves only exact preparation2 messages on the same authenticated socket.
   Private configuration1's exact linkage is never weakened or automatically disabled.
2. **Canonical source:** two root-protected canonical configuration files, independently
   pinned by raw SHA. Installed source/wheel and provider admission remain authoritative.
3. **Identity/revision:** this is one installed service process with two immutable
   configuration selections. Workflow/Job/Artifact identities and protocol families
   remain separate. Original completed requests continue using their pinned family.
4. **Pointers/checks:** verify file ancestors, owner/mode/no-symlink, bound bytes, raw
   SHA, exact schema/family, owner source and API-provider equality before constructing
   the optional runtime. Recheck the relevant selected files per operation. No latest
   fallback, untrusted path or request-supplied authority is accepted.
5. **Access:** O(1) exact message-family dispatch; actual operator capture is provided
   by the existing authenticated transport, never created or retained as a credential.
6. **Structure:** two explicitly named runtime references and one narrow preparation
   port adapter. No mutable registry, plugin framework, new listener or queue.
7. **Scale:** exactly one optional runtime, O(1) routing and bounded configuration bytes.
   Existing socket four-request capacity and global fixed numerical capacity remain
   shared. Each operation uses the existing bounded driver and owner application.
8. **Transactions:** existing per-operation IAM/source reauthorization, command
   claim/lease and original idempotency own every mutation. The routing adapter has no
   SQL, filesystem, model, publication or rollback side effect.
9. **Dependencies:** supervisor composes runtime factories only after privilege drop;
   the application adapter depends on pure contracts and the existing public port.
   No contract imports infrastructure. Private application remains bound to primary1.
10. **Failure/replay:** absence of optional selection preserves old startup. A selected
    but invalid optional configuration fails startup rather than silently disabling it.
    Unsupported preparation2 fails explicitly; it never falls back to primary1.
    Replay uses the original request identity/family. Rollback deselects only the
    optional activation; canonical outputs, old private configuration and history stay.
11. **Simpler alternative:** replacing primary1 with mixed2 would break private1's
    genuine configuration linkage. A second privileged service/listener would duplicate
    installation/authentication/capacity ownership. Explicit bounded cohosting reuses
    the existing owner without changing private semantics or introducing that framework.

This note does not activate a configuration. Source, installed compatibility and
actual authenticated preparation/read acceptance remain separate evidence gates.
