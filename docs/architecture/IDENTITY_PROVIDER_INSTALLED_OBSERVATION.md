# Actual installed Identity provider observation

2026-10-13 UTC. Original incremental-index goal continuation. Existing receiver,
one-use transport/capture and current session fence remain unchanged.

1. Boundary: trusted root composition observes the actual existing API; its
   dedicated controller verifies that observation before/after the fixed exchange.
   This is an Identity infrastructure adapter, not an alternative authenticator.
2. Canonical source: exact reviewed API wheel/source, root-protected non-secret
   API configuration, protected API key-file metadata and current kernel process.
   No model/request chooses these pins or the installed peer.
3. Identity: preserve commit, wheel raw SHA, config raw SHA, process PID/start ticks
   and systemd InvocationID separately. No new DB entity/revision or cached grant.
4. Resolution: actual unit/UID/process lifetime, installed capture/authentication
   code bytes, held file/directory epochs and fixed paths must still agree. Source
   byte checks cover the declared authentication boundary, not a new whole-host
   attestation of every third-party API library. Ordinary API deployment trust
   remains the existing product boundary.
5. Access: exact fixed process/unit/file lookup, bounded code/config hash checks
   and descriptor epochs. No corpus, credential or token-table scan.
6. Structures: frozen small local configuration plus owned held descriptors.
   The existing JSON Schema2020-12 capture request/response is the only wire message.
   Local immutable values with no independent lifecycle do not need a new registry.
7. Scale: one process, one config, one key metadata witness and bounded first-party
   authentication files; O(declared bytes) initial/current verification. No dependency.
8. Concurrency: capture actual process/stat and unit identity before dropping to
   controller UID; recheck on every admission assertion and late after the exchange.
   Retained proc/stat descriptor rejects process exit/reuse. No SQL is held.
9. Dependency: Identity implements its existing provider-admission interface;
   Orchestrator's fixed API client consumes it through trusted composition.
   Domain/contracts import no filesystem/process infrastructure.
10. Failures: closed/replaced descriptors, PID/unit/release/config/key change,
    writable/foreign files or missing observation fail explicitly. No refresh,
    reconnect, root auth copy, forged operator, repaired grant or latest substitution.
11. Simpler alternative: an HTTP build-info response or callback returning None
    cannot bind current protected key ownership and actual process. A few held
    metadata descriptors close that gap without another service, queue or IPC framework.

## Secret boundary and trust

Root opens the existing secret path **O_PATH only**. The controller may inspect
its stat/ownership/current name, never read key bytes: O_RDONLY secret descriptors
are rejected. Non-secret configuration/code descriptors are read-only. Root
passes those exact handles through the supported one-shot process composition,
not through Worker messages or persisted user tokens. Their inspection is not an
operator/source grant; the official HMAC capture and every current IAM/source/root
fence are still mandatory. No worker gains API-secret, PostgreSQL or NAS access.

Only the declared fixed API code paths are accepted. Configuration namespace
replacement changes its held parent epoch; secret replacement or in-place writes
change its name/epoch. Process and unit checks bind the exact installed API lifetime.
Root/approved deployment must keep it unchanged during the finite operation.
This adapter does not claim protection against a malicious root or re-seal the
separately admitted numerical CPU runtime. Installing it does not activate native work.

## Required verification

missing/closed/replaced paths, key/config/code mutation, process exit/reuse, wrong
UID/unit/InvocationID, late denial and secret-safe errors. Preserve existing receiver,
genuine synthetic-HMAC transport, permission/root/expiry and CPU admission tests.
Actual owner-UID observation is a separate opt-in OS check before real operator
capture/seed; synthetic seams must never be reported as installed authorization.
