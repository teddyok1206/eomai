## Eleven-point boundary

1. **Responsibility.** Close the smallest real Linux executable/loader/tool boundary,
   compose the already implemented wheel and Conda audits into whole-prefix admission,
   and place that admission before the first **protected successor** instruction in the
   existing publisher. Then implement the existing required factory admission port.
   No solver, downloader, generic command broker, new provider/registry or permanent
   UNAVAILABLE implementation is proposed.
2. **Canonical source.** OS files remain the canonical host installation; their reviewed
   paths/aliases/raw pins and current dependency graph are small installation evidence.
   Public/private/Conda archives remain one canonical raw file per SHA/basename under
   `/opt/eom/embedding-runtime-archives`. Prefix bytes are an explicit executable
   materialization. Model payload/legacy manifest/old CPU prefix remain unchanged.
3. **Identity.** Separate old-bootstrap acceptance, host-capture raw SHA, source commit/
   source-tar raw SHA, each archive raw SHA, prefix-tree SHA, pre-execution receipt and
   final admission receipt from numerical proof/bundle/config IDs/revisions/raw/semantic
   hashes. Host or EOM release provenance does not replace the small numerical fingerprint.
   Use immutable named revisions and separately accepted expected raw pins, never latest.
4. **Resolution.** Root-protected ownership/modes/ancestors, regular nlink1/no capabilities,
   exact aliases, held FDs/named epochs and actual SHA/size precede ELF parsing or execution.
   Check actual ELF64/little-endian/x86_64, loader, SONAME/NEEDED, search routes and version
   requirements. A declared host hash, root JSON, PID, copied proof or version string is
   not acceptance. Unsupported routes/types/metadata deny rather than broaden the set.
5. **Access.** Fixed SONAME→candidate map, member→source-owner map, alias→target map and
   DFS/deque for dependency closure; sets deduplicate shared targets and close inventory.
   No directory search per SONAME, repeated hashing of immutable members or runtime Git.
6. **Structures.** Reuse `NumericalRuntimeFileSnapshots`, authoritative wheel core and
   Conda core. Add one stdlib fixed-Linux host adapter and one later typed native receipt
   adapter implementing the **existing** `NativeEmbeddingInstallationAdmission`.
   Captured FDs/epochs are private lifetime evidence, not transferable authority DTOs.
7. **Bounds.** Host seed≤32 regular files/64 aliases/128KiB cache; whole-host closure≤256
   distinct files, full prefix≤100,000 members/16GiB, ELF files≤1024 and dependency edges≤8192.
   Stream bytes; metadata≤1MiB per readelf child,10s absolute per child/90s host capture.
   Larger legitimate closure requires reviewed bounds, not truncation. Cost is O(bytes+
   members+dependency edges), plus sorted O(members log members) receipt inventory.
8. **Concurrency.** Retain existing profile publication reservation through promotion,
   audit and first successor call. Execute fixed tool bodies through their held verified
   executable FDs. Retain loader/library/cache/alias epochs and require root OS maintenance
   drain/no-change ownership; executable FD binding alone does **not** freeze the loader
   or all libraries. Current host/prefix drift denies and requires a new accepted capture.
9. **Ownership/dependencies.** Initial root audit uses only the independently accepted
   historical `/opt/eom/conda/envs/eom-embedding-experiment/bin/python3.12 -I -S -B`
   and admitted root-private source snapshot. `/srv/...` has an eom-owned ancestor and
   is not a root bootstrap. New worker UIDs only read admitted runtime/model/config;
   never gain eom/old-CPU groups, sudo or Docker. No Python dependency is added.
10. **Failure/replay.** Missing historical acceptance/host pins/source/current wheel,
    unsafe loader, mismatch, partial publication or lost epoch returns content-free failure
    before the new instruction. Reserve receipts O_EXCL, fsync/read-back/parent-fsync;
    incomplete or changed same-key evidence is preserved/refused. No overwrite, restore,
    chmod, bytecode rebuild, re-encode or package/RECORD repair to pass.
11. **Simpler alternative.** A tree hash, pip-check, static version or asserting a parsed
    receipt cannot establish source/loader closure. Conversely a new general installer
    is unnecessary: extend the existing publisher's one ordering seam and actual adapters.
    Synthetic ordering/lifetime/closure tests precede root's bounded real owner run.

## Concrete host capture and fixed executable-FD seam

`capture_protected_embedding_host(...)` receives independently accepted fixed candidate
raw pins through the protected owner release inputs, then actually closes the graph;
it does not deserialize an "admitted" field. Keep these small local pin values integer-only,
closed/exact-type revalidated and bounded before IO. Use existing protected snapshots
for regular bytes; the host adapter owns only explicit OS-alias/cache/ELF mechanics.

First close readelf/zstd seed without asking unadmitted readelf to certify itself:
bounded stdlib inspection of **only** Linux ELF64 header/program/dynamic string tables
checks machine, loader, NEEDED and absence of unexpected search flags/routes. Resolve
the exact pinned seed aliases/cache/native candidates and raw files first. This is a
small purpose-specific bootstrap reader, not a general ELF linker or foreign parser.
Its output and independent owner pins must agree. Then the admitted readelf may inspect
version requirements/definitions and prefix ELF details under the fixed argv:

```text
/usr/bin/readelf --wide --file-header --program-headers --dynamic --version-info /proc/self/fd/<member-fd>
```

Execute its already verified regular target through `executable=/proc/self/fd/<tool-fd>`
with only those held descriptors inherited; fixed argv0 remains `/usr/bin/readelf`.
Likewise zstd has only `/usr/bin/zstd -q -d -c`, held executable FD, owned stdin/stdout,
stderr null, fixed cwd and scrubbed environment. The narrow concrete host object exposes
only fixed readelf inspection and fixed zstd opening, **never arbitrary argv/executable**.
The Conda reader retains its current bounded duplex/lifecycle logic, but delegates its
one spawn site to this fixed FD-bound seam; no fake handle/provider default.
It continues to require the existing `CondaArchiveToolAdmission.assert_current()->None`.
The same purpose-specific port now requires `open_zstd()->Popen[bytes]` before intake;
the mechanical reader owns its existing absolute deadline, duplex IO and reaping.
There is no named-executable fallback. No member-inventory change is needed in this
first host phase; that separate later composition seam remains unimplemented.
