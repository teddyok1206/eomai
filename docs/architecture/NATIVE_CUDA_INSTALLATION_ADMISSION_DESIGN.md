# CUDA installation evidence and live admission

2026-10-16 UTC. Protocol-first successor to the CPU-only ROOTLOCAL receipt1.0.
Source implementation is not an installed receipt, kernel/device proof or grant.
The [original goal](SYSTEM_RAG_SIMILARITY_AND_INCREMENTAL_EMBEDDING_DESIGN.md)
still requires C1–C5 and six real CPU/CUDA comparisons/conditional default.

## Responsibility and required design procedure

1. Extend the existing protected installation/admission boundary with an explicit
   CUDA-only receipt2.0. Preserve strict CPU1.0 bytes, parser, profile and empty
   supplementary-group meaning; never relabel a CPU receipt as CUDA.
2. Canonical facts are the root-audited immutable prefix/inventory, independently
   pinned config1.2, installed proof/bundle, CUDA host snapshot/base snapshot and
   actual root-observed fixed-unit probe/termination. A metadata claim is not
   proof that these observations happened.
3. Reuse configuration ID/revision and existing immutable receipt storage. Inventory,
   host, device/runtime and raw/semantic hashes remain distinct. No new DB/registry.
4. Close every raw/semantic/revision/profile pointer. Reuse inventory1.0 and public
   proof/bundle/host contracts. Require exact config1.2/CUDA and the inventory boot
   to match the actual proof/device boot. Resolve driver/version through the exact
   CUDA snapshot, not a system-wide cache or latest fallback.
5. Dominant operations are fixed-key pointer lookup, ordered four-device validation,
   equality/hash checks and one held physical-lease identity.
6. Use frozen typed values, role-indexed fixed mappings and ordered tuples. Keep
   common bounded JSON/UTC/hash/unit-fact rules authoritative in the existing
   ROOTLOCAL contract module; do not copy a second parser or add a generic framework.
7. Receipt <=32KiB/depth16; four character-device nodes and one lease. Metadata
   checks are linear in bounded bytes/inventory entries; maps/sets handle identity
   and uniqueness. Large binaries remain outside DB/Git and are not copied here.
8. Existing root installation owner alone seals after observing the real probe and
   terminal cleanup. Same fixed profile lock protects installation; operational
   compute admission and the shared GPU flock remain separate. Never mutate a
   prior failed receipt/inventory or create a replacement on unknown outcome.
9. Contracts contain pure values/schema/reference validation only. Existing OS,
   systemd, GPU lease, host/FD and artifact adapters own observations/lifecycle;
   no contract imports infrastructure, subprocess, SQL or NAS behavior.
10. Missing/stale/hash/boot/device/lease/profile/termination mismatches fail closed.
    Re-reading a receipt revalidates current files/account/host/device identities;
    it cannot retroactively attest safety at the first candidate instruction.
11. Broadening the CPU receipt/empty-group rule or treating BYTE_AUDITED as a CUDA
    grant would be simpler but wrong. A distinct explicit successor preserves
    history and makes the actual device/lease prerequisites unambiguous.

## Receipt2.0 scope

- Existing config/inventory/proof/bundle/runtime/raw/semantic pins.
- Exact CUDA host snapshot pointer and existing CUDA device capture (numeric
  hardware/driver, physical UUID, PCI, minor0 and boot).
- Ordered `/dev/nvidia0`, `/dev/nvidiactl`, `/dev/nvidia-uvm`,
  `/dev/nvidia-uvm-tools` character-node epochs and major/minor pairs. No arbitrary
  paths or extra render/GPU nodes. UVM major is captured, not guessed.
- One root-provisioned tmpfs `GPU0` flock inode with parent0750/file0640, root UID,
  exact shared group, regular/nlink1/empty file and the probe holder PID/start.
- CUDA-only no-model/no-tokenizer/no-forward probe recipe; one initialization and
  synchronization, exact singleton supplementary shared-lease group, terminal
  process/cgroup/probe-GPU-client counts0 and ordered UTC termination/seal.

These are **declared metadata**, not a live FD, actual syscall log, signed seal,
permission or compute grant. Raw pins must come from the reviewed installed root
composition, never model/request authority. Observations must independently verify
the worker-reported process/FD/maps/device/lease facts before sealing. The parser
must reject constructing/copying values to smuggle unknown fields, bool integers,
floats, alternate raw JSON, CPU profiles or a wrong predecessor schema.

2. First-instruction kernel/mapping/sandbox proof for the fixed CUDA probe, narrow

## Fixed resource-file capture (before the actual CUDA probe)

1. Responsibility: the existing native-probe infrastructure captures four device
   **O_PATH** handles and observes an already-held shared-lease FD. It neither
   initializes CUDA nor opens a device for read/write, acquires/releases the lease,
   launches a process or grants numerical ownership.
2. Canonical sources are actual fstat/named inode/rdev/flags, fixed `/dev` and shared
   lease parents, current proc process identity and that exact FD's `fdinfo` lock.
3. These are boot/process-scoped frozen facts, not new persistent entities. Keep
   native config/inventory/model identities separate; no new table or Artifact.
4. Reuse receipt2.0 device/lease values and public fixed node specifications. Actual
   UUID/PCI/model/minor/driver/boot readback reuses the installed-proof OS adapter;
   proc readback alone does not establish compute capability or GPU accessibility.
5. Access patterns: four fixed-key captures, named/FD equality, bounded per-FD
   kernel record lookup and repeated liveness/epoch checks through caller scope.
6. Ordered tuples plus held descriptor records; reuse the existing shared GPU
   lease package as a borrowed concrete handle, without a second mutex/backend.
7. O(4 + bounded16KiB fdinfo + the existing lease's bounded1MiB mountinfo) check,
   not a global `/proc/locks` scan or model/prefix rehash. No payload copy or new
   dependency is needed; the existing optional shared-lease package stays lazy.
8. Acquire no new lock and never close/unlock the borrowed guard. Close every
   owned O_PATH/directory FD, including partial capture/failure. Actual owner still
   holds the lease through CUDA sync/teardown/process exit and cleanup fencing.
9. Move the shared pure Linux proc-stat start parser out of the CPU/systemd owner
   into a small process-identity module; CPU keeps its stable public wrapper/error.
   The CUDA adapter imports no Orchestrator/systemd code. Contracts remain pure.
10. Reject stale PID/start, changed handle/parent/node/rdev/flags, wrong/unheld/shared/
    POSIX/OFD lock, mismatching group and ambiguous records. Never repair paths,
    create lock files, chmod/chown device/input data or fall back to another FD.
11. A filename plus process-level `/proc/locks` entry is insufficient: the same PID
    can open another unheld description of that inode. Validate the actual borrowed
    FD's lock record instead. Do not implement `CudaEmbeddingOwnership.assert_owned`
    on this PATH-only capture or pass it to the model factory as a compute grant.

Primary ABI evidence: Linux [`show_fd_locks` implementation](https://github.com/torvalds/linux/blob/v6.8/fs/locks.c)
filters the file description, and [`flock(2)`](https://man7.org/linux/man-pages/man2/flock.2.html)
defines duplicate-description lifetime. A local unprivileged temporary tmpfs fixture
actually showed one lock record on the held FD and its duplicate, but none on a
separate open of the same inode. This was not the production GPU lock or a device
probe; it proves only the observed kernel distinction used by the regression.
