## Required design procedure

1. Responsibility: contracts own exact role-version and provenance rules; existing
   evaluation application owns canonical admission/staging, provider owns bounded
   local inference, existing Orchestrator publisher owns NAS commit.
2. Canonical source: pinned original TRAIN source/review/authorization, immutable
   training command/result, adapter files/manifest and baseline command.
3. Identity: same evaluation logical run/revision/content-hash model; successor
   wire changes command identity. No old run/output or adapter receipt rewrite.
4. Pointers: preserve artifact/revision/member/schema/media/hash checks and validated
   full training metadata closure before adapter bytes. Do not infer latest revision.
5. Access: closed version lookup, indexed artifact resolution, ordered at-most2
   cases/four arms-per-case outputs, set membership/duplicate rejection.
6. Structures: existing immutable DTOs/maps/manifests; O(metadata bytes + case count)
   admission, O(output pixels) verification, bounded by existing budgets. No DB/index,
   queue/cache/framework or large-value persistence change.
7. Concurrency: existing staged identity, GPU physical lease and no-write terminal
   receipt replay. A timeout or unsupported wire is not permission to resubmit.
8. Dependency direction: shared exact version rule lives in contract pin owner;
   infrastructure uses public codec, source parser and result validator. No worker
   direct communication, DB/NAS write, new privilege or external API.
9. Failure: unknown/crossed schemas, hash/lifecycle/permission/case mismatch fail
   before weights/models; failed receipts remain failed and replay without generation.
10. Retry/idempotency: preserve declared input hash and existing terminal receipt.
    New adapter/input/version requires new immutable evaluation identity.
11. Simpler alternative: only admit old target1.2/training1.0. Insufficient for
    reviewed exterior derivatives; broadening old wires would invalidate reproducibility.
