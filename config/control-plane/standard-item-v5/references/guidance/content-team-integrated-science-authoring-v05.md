[문항 제작 요청]
한국 수능형 모의고사 문항을 아래 요청 사항에 맞게 제작할 것.
문항 제작 시 세부 내용별로 [세부내용별 문항 범위 검증 for remind]를 반드시 참조할 것.

[최우선 연동 원칙]
- GPT가 생성하는 문항 Markdown과 HwpQuestionEditor가 읽는 Markdown은 동일한 원문 규격을 사용한다.
- 생성되는 각 `.md` 파일에는 문항과 HwpQuestionEditor가 인식해야 하는 해설만 넣는다.
- `.md` 파일에는 제목용 `#`, `##`, `###`, Markdown bold `**...**`, 수평선 `---`, 코드 블록 울타리 ```를 넣지 않는다.
- 파일명이나 문항명을 파일 첫 줄의 Markdown 제목으로 다시 적지 않는다.
- 문항 번호는 `1.`, `2.`처럼 일반 텍스트로 시작하고 `**1.**`처럼 굵게 표시하지 않는다.
- 배점은 발문 마지막에 `[2.5점]`처럼 일반 텍스트로 적고 `**[2.5점]**`처럼 굵게 표시하지 않는다.
- 정답은 반드시 한 줄에 `정답 : ③ (ㄱ, ㄷ)` 형식으로 적는다. 번호 뒤 괄호에는 해당 번호가 나타내는 실제 정답 내용을 함께 적는다.
- ㄱ/ㄴ/ㄷ 조합형은 정답 조합을 괄호에 적고, 그 밖의 선택형은 해당 선택지의 핵심 답 내용을 괄호에 적는다. 정답 번호만 단독으로 적지 않는다.
- `[정답]`이라는 구역 제목을 만들거나, 정답 번호를 다음 줄에 따로 적지 않는다.
- 해설 구역 이름은 아래 네 가지를 정확히 사용한다.
  - `[출제의도]`
  - `[개념출처]`
  - `[풀이 및 정답 해설]`
  - `[오답 해설]`
- `[출제 의도]`처럼 이름 안에 임의의 공백을 넣거나 다른 표현으로 바꾸지 않는다.
- 교과서 범위 검증, 단원별 교과서 대조를 포함한 논문 범위 검증, 출제 적합성 검토는 사용자에게 답변으로 보여주되 생성되는 `.md` 파일에는 넣지 않는다.
- 그림 제작 프롬프트도 사용자에게 답변으로 별도 제시하되 생성되는 문항 `.md` 파일에는 넣지 않는다.
- 탐구/실험형 문항은 답변에서 `HwpQuestionEditor의 탐구/실험형 문항 체크 필요`라고 안내하되, 이 안내 문구를 문항 `.md` 파일에는 넣지 않는다.

[문항 결과 산출 방법]
- 문항이 여러 개이면 문항마다 별도의 `.md` 파일을 생성한다.
- 답변에서는 각 문항을 다음 순서로 제시한다.
  1. 문항명 또는 문항 번호를 답변용 제목으로 표시한다. 이 제목은 `.md` 파일 내용에 포함하지 않는다.
  2. 실제 `.md` 파일과 완전히 동일한 내용을 Markdown 코드 블록으로 한 번 보여준다.
  3. 코드 블록 밖에서 교과서 범위 검증을 보여준다.
  4. 논문 또는 외부 연구를 사용했다면 코드 블록 밖에서 단원별 교과서 대조를 포함한 논문 범위 검증도 보여준다.
  5. 그림이 필요하면 코드 블록 밖에서 그림 제작 프롬프트를 보여준다.
  6. 실제 `.md` 파일을 첨부한다.
- 코드 블록 안의 미리보기와 실제 `.md` 파일의 내용은 완전히 동일해야 한다.
- `[교과서 범위 검증]`, `[논문 범위 검증]`, `[출제 검증]` 등의 메타 검증 구역은 미리보기 코드 블록과 실제 `.md` 파일 모두에서 제외한다.
- `[개념출처]`는 해설의 일부이므로 실제 `.md` 파일에 유지한다. `[개념출처]`와 범위 검증을 혼동하지 않는다.
- 문항과 해설은 문항별로 붙여서 순차적으로 제시한다. 예: 9회 2번 문항+해설, 9회 3번 문항+해설.

[HwpQuestionEditor용 단일 파일 템플릿]

일반 문항의 실제 `.md` 파일은 원칙적으로 다음 순서를 사용한다. 아래 템플릿의 시각자료 블록은 `표 2개`인 경우의 예시이며, 다른 시각자료 조합은 [시각자료 Markdown 생성 규약]의 6가지 canonical case 중 하나로 교체한다.

```text
1. 문제 발문을 적는다.

필요한 조건이나 자료를 적는다.

표 (가)

| 열 1 | 열 2 |
|---|---|
| 내용 | 내용 |

표 (나)

| 열 1 | 열 2 |
|---|---|
| 내용 | 내용 |

이에 대한 설명으로 옳은 것만을 <보기>에서 있는 대로 고른 것은? [2.5점]

<보기>

ㄱ. 선지 내용

ㄴ. 선지 내용

ㄷ. 선지 내용

① ㄱ
② ㄴ
③ ㄱ, ㄷ
④ ㄴ, ㄷ
⑤ ㄱ, ㄴ, ㄷ

정답 : ③ (ㄱ, ㄷ)

[출제의도]

ㄱ. 출제 의도

ㄴ. 출제 의도

ㄷ. 출제 의도

[개념출처]

이 문항은 (대단원명) 단원 중 (중단원)에 대한 문항입니다.

[풀이 및 정답 해설]

세 선지 모두의 판단에 공통으로 필요한 내용이 있을 때만 전체 해설을 먼저 적는다. 그렇지 않으면 이 문단을 생략한다.

ㄱ. 맞는 선지 해설 또는 [풀이] 참조

ㄷ. 맞는 선지 해설 또는 [풀이] 참조

[오답 해설]

ㄴ. 틀린 선지 해설 또는 [풀이] 참조
```

위 템플릿에서 다음을 지킨다.
- 실제 파일에는 위 코드 블록의 시작과 끝을 나타내는 ```를 넣지 않는다.
- `문항`, `해설`을 나타내는 `## 문항`, `## 해설` 구역을 추가하지 않는다.
- 문항과 해설 사이에 `---`를 넣지 않는다.
- 선택지는 ①부터 ⑤까지 각각 한 줄에 하나씩 적는다.
- 선택지 줄 끝에 Markdown 강제 줄바꿈용 공백 두 칸을 넣지 않는다.
- 정답 줄은 선택지 다음에 배치하며 `정답 : ③ (ㄱ, ㄷ)`을 한 줄로 유지한다.
- 해설 작성의 기본 우선순위는 `선지별 해설 작성 → 전체 해설 생략`이다.
- 전체 해설은 ㄱ, ㄴ, ㄷ 세 선지를 판단하는 데 모두 필요한 공통 개념, 공통 계산 또는 공통 자료 해석이 있을 때만 사용한다.
- 한두 선지에만 필요한 내용은 전체 해설에 쓰지 말고 해당 선지별 해설에 적는다.
- 전체 해설이 있으면 선지별 해설보다 먼저 적고 별도의 `[전체 해설]` 제목은 만들지 않는다.
- 전체 해설에서는 세 선지에 공통인 풀이의 토대만 제시하고, 각 선지의 정오 판단은 선지별 해설에서 이어서 적는다.
- 전체 해설에서 특정 선지의 판단 근거를 이미 완전히 설명했다면 해당 선지별 해설에는 같은 내용을 반복하지 않고 `ㄱ. [풀이] 참조`와 같이 적는다.
- 전체 해설에서 특정 선지의 판단 근거를 일부만 설명했다면 선지별 해설에는 공통 내용을 반복하지 말고 그 선지에 추가로 필요한 판단만 적는다.
- 전체 해설이 없으면 별도 내용을 만들지 말고 곧바로 선지별 해설을 시작한다.
- 맞는 선지의 해설만 `[풀이 및 정답 해설]`에 적는다.
- 틀린 선지의 해설만 `[오답 해설]`에 적는다.
- ㄱ, ㄴ, ㄷ은 각각 한 번만 해설하며, 직접 해설하지 않는 선지는 반드시 `[풀이] 참조`로 처리한다.

탐구/실험형 문항은 다음을 지킨다.
- 문항 성격에 따라 `[탐구 목표]`, `[탐구 과정]`, `[탐구 결과]` 또는 `[실험 목표]`, `[실험 과정]`, `[실험 결과]`를 사용한다.
- `탐구`와 `실험` 표현을 임의로 서로 바꾸지 않는다.
- 목표가 불필요한 문항은 `[탐구 목표]` 또는 `[실험 목표]` 구역 전체를 생략한다.
- 탐구/실험 과정은 최소 3개 이상 구성한다.
- 탐구/실험 과정은 실제 수행 시간 순서대로 제시한다.
- 한 과정에는 하나의 주요 조작이나 절차를 중심으로 적고, 여러 과정을 한 단계에 과도하게 묶지 않는다.
- 탐구/실험 과정에는 조작과 절차만 적고 결과를 넣지 않는다.
- 과정에서 얻은 결과는 `[탐구 결과]` 또는 `[실험 결과]` 아래에 적는다.
- 과정의 표시는 `(가)`, `(나)`, `(다)`, `(라)`, `(마)`, `(바)`, `(사)`, `(아)` 순서로 필요한 만큼 계속 작성할 수 있다.
- 탐구/실험 결과 안에 표가 필요하면 해당 구역 내부에 Markdown table 자체를 작성한다.
- 탐구/실험 결과의 Markdown table 앞에도 독립된 한 줄의 `표`를 추가하지 않는다.
- 탐구/실험형 문항은 기존 inquiry box를 사용하므로 일반 문항의 자동 visual-slot 규칙과 혼용하지 않는다.
- 탐구/실험형에서 별도 그림 파일이 필요하면 그림 제작 프롬프트는 답변에서만 제공하고, 실제 그림 삽입은 별도 작업으로 처리한다. `.md`에는 이미지 파일 경로, 이미지 URL, Markdown image syntax, 이미지 제작 프롬프트를 넣지 않는다.
- 탐구/실험형 `.md` 파일을 HwpQuestionEditor에서 불러올 때 사용자가 GUI의 `탐구/실험형 문항`을 체크해야 한다.

[Markdown 파일 제작 규칙]
- 한 파일에는 원칙적으로 문항 하나만 넣는다.
- 파일은 UTF-8 Markdown 원문으로 생성한다.
- HwpQuestionEditor는 Markdown 전체를 렌더링하는 프로그램이 아니므로 문항 파일에서는 불필요한 Markdown 장식을 사용하지 않는다.
- 허용하는 주요 Markdown 문법과 HwpQuestionEditor용 semantic marker는 다음과 같다.
  - 수식 구분자 `$...$`, `$$...$$`
  - 표 문법 `| ... |`
  - 해설 및 탐구/실험 구역을 나타내는 지정된 대괄호 레이블
  - IMAGE slot marker `그림`, `그림 (가)`, `그림 (나)`
  - 표가 2개일 때 각 Markdown table을 식별하는 semantic label `표 (가)`, `표 (나)`
- 문항 파일에서 사용하지 않는 문법과 표현은 다음과 같다.
  - `#`, `##`, `###` 제목
  - `**...**`, `*...*` 강조
  - `---` 수평선
  - 인용문 `>`
  - 코드 블록 ```
  - HTML 태그
  - Markdown image syntax `![대체 텍스트](이미지 경로)`
  - 이미지 파일 경로, 이미지 URL, 이미지 제작 프롬프트
- 파일 안에서 굵게 표시할 위치는 Markdown bold로 만들지 않는다. HwpQuestionEditor가 template과 renderer 규칙에 따라 처리하도록 원문에는 지정된 레이블과 일반 텍스트만 넣는다.
- 시각자료의 marker와 semantic label은 아래 [시각자료 Markdown 생성 규약]만 따른다.

[시각자료 Markdown 생성 규약]

## 1. 기본 원칙
- 문제 발문에 들어가는 `그림은 ...`, `표는 ...`, `그림은 ..., 표는 ...`, `표는 ..., 그림은 ...`, `그림 (가)는 ..., (나)는 ...`, `표 (가)는 ..., (나)는 ...` 등의 표현은 자료를 설명하는 발문 문장이다.
- 실제 `.md`에서 HwpQuestionEditor가 시각자료의 위치와 종류를 판단할 때는 아래의 canonical visual 구조를 사용한다.
- 발문 속의 `그림`, `표`라는 단어와 실제 visual marker 또는 Markdown table을 중복된 자료로 계산하지 않는다.
- 그림 제작 프롬프트는 기존 규칙대로 답변에서만 별도로 제공하고 실제 문항 `.md`에는 넣지 않는다.

## 2. 그림 marker의 exact format
- HwpQuestionEditor용 `.md`에서 IMAGE slot marker는 독립된 한 줄의 `그림`, `그림 (가)`, `그림 (나)` 세 가지 형식만 사용한다.
- `그림은 ...`, `그림에서 알 수 있는 것은 ...`, `그림과 같이 ...`는 일반 발문이며 IMAGE slot marker가 아니다.
- `그림 삽입`, `[그림 자리]`, `[이미지 자리]`, `이미지`, 이미지 파일 경로, 이미지 URL, Markdown image syntax, 이미지 제작 프롬프트를 실제 문항 `.md`에 사용하지 않는다.

## 3. 표의 식별 원칙
- 표가 1개인 모든 경우에는 Markdown table 자체가 TABLE visual item이다.
- 표만 있는 문항, `그림 + 표`, `표 + 그림`, 탐구/실험 결과 내부의 표에서 독립된 한 줄의 `표`를 만들지 않는다.
- `표 (가)`와 `표 (나)`는 TABLE/TABLE, 즉 표가 2개인 경우에만 각각 바로 다음 Markdown table을 식별하는 semantic label로 사용한다.

## 4. 일반 문항의 6가지 canonical visual case

### 4.1 그림 1개
발문은 `그림은 ~~를 나타낸 것이다.` 형식으로 쓰고 실제 그림 위치에는 독립된 한 줄 `그림`만 작성한다.

```text
1. 그림은 A와 B의 운동을 나타낸 것이다.

그림

이에 대한 설명으로 옳은 것은? [2.5점]
```

실제 `.md`에는 `그림 삽입`, `[그림 자리]`, `[이미지 자리]`, `이미지`, 이미지 파일 경로, Markdown image syntax, 이미지 제작 프롬프트를 넣지 않는다.

### 4.2 표 1개
발문은 `표는 ~~를 나타낸 것이다.` 형식으로 쓰고 실제 `.md`에는 Markdown table 자체만 작성한다. 표 앞에 독립된 `표`라는 줄을 만들지 않는다.

```text
1. 표는 A와 B의 특성을 나타낸 것이다.

| 대상 | 값 |
|---|---|
| A | $3$ |
| B | $5$ |

이에 대한 설명으로 옳은 것은? [2.5점]
```

### 4.3 그림 1개 + 표 1개
발문은 `그림은 ~~를, 표는 ~~를 나타낸 것이다.` 형식으로 쓰고 실제 `.md`는 `IMAGE → TABLE` 순서로 작성한다. `(가)`, `(나)`를 붙이지 않으며 별도의 `표` line을 만들지 않는다.

```text
1. 그림은 판 $A$ ~ $C$와 관측점의 위치를, 표는 각 판의 특성을 나타낸 것이다.

그림

| 대상 | 자료 |
|---|---|
| A | 내용 |
| B | 내용 |

이에 대한 설명으로 옳은 것은? [2.5점]
```

다음 구조는 생성하지 않는다.

```text
그림

표

| 대상 | 자료 |
|---|---|
| A | 내용 |
```

### 4.4 표 1개 + 그림 1개
발문은 `표는 ~~를, 그림은 ~~를 나타낸 것이다.` 형식으로 쓰고 실제 `.md`는 `TABLE → IMAGE` 순서로 작성한다. `(가)`, `(나)`를 붙이지 않으며 표 앞에 별도의 `표` line을 만들지 않는다.

```text
1. 표는 A와 B의 특성을, 그림은 A와 B의 위치를 나타낸 것이다.

| 대상 | 값 |
|---|---|
| A | $3$ |
| B | $5$ |

그림

이에 대한 설명으로 옳은 것은? [2.5점]
```

### 4.5 그림 2개
발문은 `그림 (가)는 ~~를, (나)는 ~~를 나타낸 것이다.` 형식으로 쓰고 실제 `.md`에는 다음 두 marker만 순서대로 작성한다.

```text
그림 (가)

그림 (나)
```

이는 `IMAGE / IMAGE`를 의미한다. HwpQuestionEditor가 최종 HWPX에서 좌우 그림 영역과 `(가)`, `(나)` label을 만든다.

### 4.6 표 2개
발문은 `표 (가)는 ~~를, (나)는 ~~를 나타낸 것이다.` 형식으로 쓰고 실제 `.md`에는 각 semantic label 바로 다음에 해당 Markdown table을 작성한다.

```text
표 (가)

| 대상 | 값 |
|---|---|
| A | $3$ |

표 (나)

| 대상 | 값 |
|---|---|
| B | $5$ |
```

`표 (가)`, `표 (나)`는 표가 2개일 때만 사용한다.

## 5. 자료 순서와 중복 해석 금지
- 발문에서 자료를 설명한 순서와 실제 `.md`의 visual item 순서를 반드시 일치시킨다.
- 발문이 `그림 → 표`이면 실제 `.md`도 `그림 marker → Markdown table` 순서로 작성한다.
- 발문이 `표 → 그림`이면 실제 `.md`도 `Markdown table → 그림 marker` 순서로 작성한다.
- GPT가 임의로 자료의 순서를 바꾸지 않는다.
- `그림은 A와 B의 관계를 나타낸 것이다.` 다음의 독립 line `그림`은 그림 2개가 아니라, 발문 1개와 IMAGE marker 1개로 이루어진 그림 1개 case이다.
- `그림은 ~~를, 표는 ~~를 나타낸 것이다.` 다음의 `그림`과 Markdown table은 정확히 `IMAGE + TABLE` 2개 자료이다.

## 6. 현재 허용하는 조합과 visual item 수 제한
일반 문항의 자동 시각자료 배치는 다음 6가지 canonical case만 사용한다.

```text
그림 1개
→ 그림

표 1개
→ Markdown table

그림 + 표
→ 그림
→ Markdown table

표 + 그림
→ Markdown table
→ 그림

그림 2개
→ 그림 (가)
→ 그림 (나)

표 2개
→ 표 (가)
→ Markdown table
→ 표 (나)
→ Markdown table
```

- 이 외의 임의 형식은 만들지 않는다.
- 현재 HwpQuestionEditor의 일반 자동 visual layout은 최대 2개의 visual slot을 기준으로 하므로 실제 `.md`에 그림/표 visual item을 3개 이상 독립적으로 생성하지 않는다.
- 자료가 3개 이상 필요한 경우 출제 단계에서 최대 2개의 visual item으로 통합한다.
- 그림 3개가 필요하면 그림 하나 내부에 `(가)`, `(나)`, `(다)`를 포함하는 composite 그림으로 제작하고 실제 `.md`에는 `그림` 1개만 표시한다.
- 표 3개가 필요하면 가능한 경우 하나의 Markdown table로 통합하거나 최대 2개 표로 재구성한다.
- 이미지 내부의 `(가)`, `(나)`, `(다)` 표시는 이미지 제작 프롬프트에서 처리하며 HwpQuestionEditor에 visual slot 3개를 요구하지 않는다.
- 기존의 `자료 3개 이상이면 각각 (가), (나), (다)로 지정한다.` 규칙은 HwpQuestionEditor용 `.md` 생성에는 적용하지 않는다.

## 7. 탐구/실험형 문항
- 탐구/실험형 문항은 기존 inquiry box를 사용하므로 일반 문항의 자동 visual-slot 규칙과 혼용하지 않는다.
- `[탐구 결과]` 또는 `[실험 결과]` 내부에 표가 필요하면 Markdown table 자체를 작성하고 그 앞에 standalone `표`를 추가하지 않는다.

```text
[탐구 결과]

(가)의 결과

| 대상 | 값 |
|---|---|
| A | 내용 |
```

- 탐구/실험형에서 별도 그림 파일이 필요한 경우 기존 규칙대로 그림 제작 프롬프트를 답변에서 별도로 제공하고, 실제 그림 삽입은 별도 작업으로 처리한다.
- 탐구/실험형 `.md`에도 이미지 파일 경로, 이미지 URL, Markdown image syntax, 이미지 제작 프롬프트를 넣지 않는다.

[수식 편집 규칙]

## 1. 기본 원칙
GPT 문항 생성과 HwpQuestionEditor 한글 편집은 동일한 Markdown 원문을 기준으로 처리한다.

권장 작업 흐름은 다음과 같다.

```text
GPT 문항 생성
→ Markdown(.md) 원문 저장
→ HwpQuestionEditor에서 .md 직접 불러오기
→ Markdown/수식 parser
→ HWPX renderer
→ 한글 파일 생성
```

화면에 렌더링된 문항을 복사하여 일반 텍스트로 변환하지 않는다.
Markdown 원문의 문법과 LaTeX 수식 source를 그대로 보존하는 것을 최우선으로 한다.

## 2. 수식의 기본 표기

### 2.1 인라인 수식
문장 안에 들어가는 수식은 `$...$`로 작성한다.

```markdown
물체의 운동 에너지는 $\frac{1}{2}mv^{2}$이다.
```

```markdown
농도가 $2.0 \times 10^{-3}$ mol/L이다.
```

### 2.2 독립 수식
한 줄 또는 별도 영역에 독립적으로 들어가는 수식은 `$$...$$`로 작성한다.

```markdown
$$
v = \frac{s}{t}
$$
```

- `$` 또는 `$$`를 열었으면 반드시 닫는다.
- 닫히지 않은 수식 구분자를 생성하지 않는다.

### 2.3 범위 표시 물결표 `~`
범위나 연속된 대상을 나타내는 `~`는 하나의 수식 안에 넣지 않고 일반 텍스트로 분리한다. `~`의 양쪽 항이 변수나 수식이면 각 항을 각각 별도의 `$...$`로 감싼다.

권장:

```markdown
$A$ ~ $C$
$T_{1}$ ~ $T_{3}$
```

금지:

```markdown
$A~C$
$T_{1}~T_{3}$
```

- `A ~ C`처럼 수식으로 표시해야 하는 문자를 일반 텍스트로만 적지 않는다.
- 페이지 범위처럼 수식이 아닌 일반 숫자 범위는 `106~108쪽`과 같이 일반 텍스트로 적을 수 있다.

## 3. 분수
분수는 반드시 `\frac{분자}{분모}` 구조를 사용한다.

```markdown
$\frac{1}{2}$
```

```markdown
$\frac{a+b}{c}$
```

다음처럼 작성하지 않는다.

```text
½
1/2
(a+b)/c
```

단, `/`가 단순 비율 또는 단위 표기의 일반 문자로 의도된 경우에는 사용할 수 있다.

## 4. 아래첨자
아래첨자는 `_`와 중괄호를 사용한다.

```markdown
$CO_{2}$
$H_{2}O$
$a_{1}$
$T_{1}$
$T_{12}$
$I_{\max}$
```

다음처럼 작성하지 않는다.

```text
CO₂
H₂O
a₁
$T_1$
$T_12$
I\_{max}
```

- 수식 내부의 아래첨자 `_` 앞에 불필요한 escape backslash를 붙이지 않는다.
- 아래첨자가 숫자이면 한 자리 숫자라도 반드시 중괄호로 묶는다. `$T_1$`이 아니라 `$T_{1}$`로 적고, 여러 자리 숫자는 `$T_{12}$`로 적는다.
- 숫자 아래첨자가 붙은 항의 범위는 `$T_{1}$ ~ $T_{3}$`처럼 각 항을 별도 수식으로 쓰고 `~`를 수식 밖에 둔다.
- `$I\_{\max}$`가 아니라 `$I_{\max}$`로 적는다.
- 일반 문장에 변수 `t_1`을 직접 적지 말고 `$t_{1}$`로 적는다.

## 5. 위첨자
위첨자는 `^`와 중괄호를 사용한다.

```markdown
$x^{2}$
$10^{-3}$
$Ca^{2+}$
```

다음처럼 작성하지 않는다.

```text
x²
10⁻³
Ca²⁺
```

## 6. 위첨자와 아래첨자가 동시에 있는 경우
둘 다 구조적으로 명시한다.

```markdown
$x_{1}^{2}$
$^{14}C$
$SO_{4}^{2-}$
```

## 7. 화학식과 이온식
첨자 구조가 필요한 화학식은 반드시 수식으로 작성한다.

```markdown
$H_{2}O$
$CO_{2}$
$CaCO_{3}$
$Na^{+}$
$Ca^{2+}$
$SO_{4}^{2-}$
$NH_{4}^{+}$
```

Unicode 아래첨자와 위첨자를 사용하지 않는다.

## 8. 곱셈과 과학적 표기
곱셈 기호는 `\times`를 사용한다.

```markdown
$3.0 \times 10^{8}$
```

`×` 문자 자체보다 LaTeX source를 우선한다.

## 9. 부등호와 비교식
수식 안의 관계식은 수식 영역 안에서 표현한다.

```markdown
$a > b$
$x \leq 3$
$a \geq b$
$x \neq y$
```

## 10. 괄호
수식 구조가 명확하도록 괄호를 사용한다.

```markdown
$(a+b)^{2}$
$\frac{(a+b)^{2}}{c}$
$\left( \frac{a}{b} \right)$
```

## 11. 제곱근
제곱근은 다음과 같이 작성한다.

```markdown
$\sqrt{x}$
$\sqrt{a+b}$
$\sqrt[n]{x}$
```

## 12. 절댓값
절댓값은 수식 내부에서 표현한다.

```markdown
$|x|$
$\left| x-1 \right|$
```

## 13. 그리스 문자와 수학 기호
가능하면 LaTeX 명령어를 사용한다.

```markdown
$\alpha$
$\beta$
$\gamma$
$\theta$
$\lambda$
$\Delta$
```

## 14. 현재 HwpQuestionEditor에서 우선 사용할 안전 수식 범위
문항 생성 시 현재 프로그램에서 직접 검증된 다음 구조를 우선 사용한다.

- 일반 숫자와 영문 변수
- `+`, `-`, `=`, `<`, `>`
- `\frac{...}{...}`
- `_{...}`
- `^{...}`
- 아래첨자와 위첨자의 조합
- 화학식과 이온식의 첨자 조합
- `\times`
- `$...$`, `$$...$$`

`\sqrt`, `\leq`, `\geq`, `\neq`, 그리스 문자, 크기 조절 괄호 등은 Markdown source 형식으로는 유지하되, 해당 문항에서 실제 HWPX 렌더링 지원이 확인되지 않았다면 무리하게 사용하지 않는다. 필요한 표현이 현재 renderer의 검증 범위를 벗어나면 사용자에게 별도로 알린다.

## 15. 단위
숫자와 단위 전체를 무조건 수식으로 만들 필요는 없다.

```markdown
속력은 $20$ m/s이다.
코일의 감은 수는 $150$회이다.
```

첨자·지수·분수 등의 구조가 필요한 부분만 수식 영역에 포함한다.

## 16. 일반 텍스트와 수식의 경계
문장 전체를 불필요하게 수식으로 감싸지 않는다.

금지:

```markdown
$물체의 운동 에너지는 \frac{1}{2}mv^{2}이다.$
```

권장:

```markdown
물체의 운동 에너지는 $\frac{1}{2}mv^{2}$이다.
```

- 한글 설명은 일반 텍스트로 적는다.
- 수학·화학 구조만 `$...$`에 넣는다.
- 수식 뒤의 조사와 설명은 다시 일반 텍스트로 적는다.

## 17. 수식 내부 한글 문장 금지

권장:

```markdown
속력은 $v$이고 시간은 $t$이다.
```

금지:

```markdown
$속력은 v이고 시간은 t이다.$
```

## 18. Markdown 강조 금지
실제 문항 `.md` 파일에서는 Markdown bold와 italic을 사용하지 않는다.

금지:

```markdown
**1.** 문제 발문
**[2.5점]**
```

권장:

```markdown
1. 문제 발문
[2.5점]
```

문항 번호, 배점, 탐구/실험 제목, 출제의도 선지 표지 등의 서식은 HwpQuestionEditor가 template과 renderer 규칙으로 처리한다.

## 19. 표 안의 수식
표 안에 수식이 들어가더라도 동일한 규칙을 적용한다.

```markdown
| 물질 | 농도 |
|---|---|
| A | $2.0 \times 10^{-3}$ |
| B | $\frac{1}{2}$ |
```

## 20. 선지와 해설 안의 수식
ㄱ/ㄴ/ㄷ, ①~⑤, 출제의도, 풀이, 오답 해설, 탐구/실험 박스 안에서도 동일한 수식 규칙을 사용한다.

```markdown
ㄱ. 운동 에너지는 $\frac{1}{2}mv^{2}$이다.
① $a > b > c$
```

### Markdown escape로 LaTeX 구조를 훼손

## 22. HwpQuestionEditor 처리 원칙
HwpQuestionEditor는 Markdown 원문을 source of truth로 사용한다.

1. `.md` 파일 원문 직접 읽기
2. UTF-8 Markdown source 보존
3. `$...$`, `$$...$$` 수식 영역 식별
4. 일반 텍스트와 equation token 분리
5. LaTeX source를 수식 renderer에 전달
6. 기존 HWPX forensic/prototype 기반 수식 rendering 사용
7. 최종 HWPX 생성

수식을 화면에 보이는 Unicode 문자로 먼저 바꾼 뒤 다시 해석하지 않는다.

## 23. 자동 보정 원칙
정확한 LaTeX source가 있으면 source를 그대로 사용한다.
일반 텍스트 `CO2`, `Ca2+`, `1/2`를 문맥으로 추측하여 자동 변환하지 않는다.
입력 단계에서 구조를 정확하게 작성한다.

## 24. 최종 수식 기준
사람이 화면에서 보는 수식 모양이 아니라 수식의 구조를 보존하는 Markdown + LaTeX source를 기준 데이터로 사용한다.

## 25. 문자 및 변수 서식 일관성
동일한 문자·변수·기호는 문제 발문, 자료, 표, 그림 설명, <보기>, `[출제의도]`, `[개념출처]`, `[풀이 및 정답 해설]`, `[오답 해설]`에서 동일한 Markdown/LaTeX 표기를 유지한다.

문제 발문에서 `$Y$`로 명명한 문자는 자료, 표, 선지, 해설에서도 모두 `$Y$`로 작성하고 일반 텍스트 `Y`와 혼용하지 않는다. 한 문제와 그 해설 안에서 동일한 문자를 이탤릭체와 비이탤릭체로 혼용하지 않는다.

[전 문항 생성 공통 요청 사항]
- 기본적으로 한국교육과정평가원(KICE)의 발문 형태를 사용할 것.
- 참신하거나 특이한 선지를 적극 사용하되 교과서 범위 내에서 출제할 것.
- 난이도 높은 N제에 들어가는 문항이므로 난도를 매우 높게 설정할 것.
- `~은 ~때문이다`와 같은 인과 서술형 선지를 지양하고 `~은 ~이다`, `~은 ~보다 크다`처럼 간결하고 명확한 선지를 사용할 것.
- 선지를 짧게 쓰고 불필요한 인과 관계 형식의 선지를 지양할 것.
- 다른 단원과 적극적으로 융합할 것.
- ㄱ/ㄴ/ㄷ 형식의 선지를 사용할 것.
- 일러스트가 필요하면 그림 제작 프롬프트를 별도로 작성할 것.
- 그림 제작 프롬프트 맨 앞에는 다음 문장을 그대로 추가할 것.
  - `아래의 요청사항에 대한 문제의 그림을 그려줘. 내가 소스에 넣어둔 이미지 규칙을 잊지 말고 지켜`
- 그림 제작 프롬프트는 답변에서만 보여주고 문항 `.md` 파일에는 넣지 않을 것.
- 지엽적인 선지를 사용하면 교과서 출처를 명시할 것.
- 탐구/실험형 문항은 탐구/실험 목표, 탐구/실험 과정, 탐구/실험 결과를 명확히 구분할 것.
- 탐구/실험형 문항의 과정에는 결과를 넣지 말 것.
- 과정에 따른 결과는 탐구/실험 결과에서 `(가)의 결과`, `(나)의 결과`처럼 구성할 것.
- 문항 출제 후 모든 선지가 교과서 범위에서 출제 가능한지 검증할 것.
- 범위 검증 결과는 답변에서는 사용자에게 보여주되 생성되는 `.md` 파일에는 넣지 않을 것.

[전 문항 문제 발문 작성 요령]
- 문제 발문 문장은 Markdown 원문에서 중간에 Enter를 입력해 나누지 말고 한 줄로 끝까지 이어서 작성할 것. 자료·표·그림·<보기>를 구분하기 위한 구조적 빈 줄은 기존 규칙대로 유지한다.
- 탐구/실험형 문항의 문제 발문은 두 문장을 넘지 않게 작성할 것. 발문에 넣으려던 조건이나 절차는 탐구/실험 과정을 늘려 별도의 단계로 제시할 것.
- `$A$ ~ $D$는 각각 네 가지 경우 중 하나이다.`처럼 대상과 경우의 수가 대응하도록 제시하면 서로 다르다는 뜻이 포함되므로 `서로 다르다`를 추가하지 말 것. 이 원칙은 `$A$ ~ $C$`, `$A$ ~ $E$` 등에도 동일하게 적용한다.
- 그림형 자료를 1개 사용할 경우 발문은 `그림은 ~~를 나타낸 것이다.`로 쓰고 실제 `.md`에는 독립 line `그림`을 1개 작성할 것.
- 표형 자료를 1개 사용할 경우 발문은 `표는 ~~를 나타낸 것이다.`로 쓰고 실제 `.md`에는 Markdown table 자체만 작성할 것. standalone `표` line은 만들지 않는다.
- 그림 다음 표를 사용할 경우 발문은 `그림은 ~~를, 표는 ~~를 나타낸 것이다.`로 쓰고 실제 `.md`도 `그림 marker → Markdown table` 순서로 작성할 것. `(가)`, `(나)`는 붙이지 않는다.
- 표 다음 그림을 사용할 경우 발문은 `표는 ~~를, 그림은 ~~를 나타낸 것이다.`로 쓰고 실제 `.md`도 `Markdown table → 그림 marker` 순서로 작성할 것. `(가)`, `(나)`는 붙이지 않는다.
- 그림 2개를 사용할 경우 발문은 `그림 (가)는 ~~를, (나)는 ~~를 나타낸 것이다.`로 쓰고 실제 `.md`에는 `그림 (가)`, `그림 (나)`를 순서대로 작성할 것.
- 표 2개를 사용할 경우 발문은 `표 (가)는 ~~를, (나)는 ~~를 나타낸 것이다.`로 쓰고 실제 `.md`에는 `표 (가)` + table, `표 (나)` + table을 순서대로 작성할 것.
- 발문 속 `그림은`, `표는`은 자료 설명 문장이며 실제 visual item으로 중복 계산하지 않는다.
- 발문에서 자료를 언급한 순서와 실제 `.md`의 visual item 순서를 반드시 일치시키고 GPT가 임의로 바꾸지 않는다.
- 일반 문항의 실제 `.md`에는 최대 2개의 visual item만 생성한다. 자료가 3개 이상 필요하면 하나의 composite 그림, 하나의 통합 표 또는 최대 2개 visual item으로 재구성한다.
- 기존의 `자료 3개 이상이면 각각 (가), (나), (다)로 지정한다.` 규칙은 HwpQuestionEditor용 `.md` 생성에는 적용하지 않는다. composite 그림 내부의 `(가)`, `(나)`, `(다)` 표시는 이미지 제작 프롬프트에서 처리한다.
- 탐구/실험형 문항은 자료를 제시할 때 위 일반 자료 발문 규칙을 반드시 따를 필요가 없지만, 결과 내부의 Markdown table 앞에는 standalone `표`를 추가하지 않는다.
- 시점이나 시간을 나타낼 때는 `$t$`, `$t_{1}$`, `$T$`와 같은 표현을 적극적으로 활용할 것.
- 수식 변수는 일반 텍스트 `t_1`이나 escaped text `t\_1`이 아니라 LaTeX 수식 `$t_{1}$`로 작성할 것.
- 표·그림·자료 안에 들어갈 변수명 또는 물리량 설명이 5글자를 초과하면, 문제 발문에서 그 의미를 먼저 설명한 뒤 특정 문자로 치환하여 정의할 것.
- 예를 들어 표 안의 변수명이 `용질 1 mL에 들어 있는 $H^{+}$ 또는 $OH^{-}$의 상대적 개수`인 경우, 발문은 `표 (가)는 HCl 수용액 A, B와 NaOH 수용액 C의 용질 1 mL에 들어 있는 $H^{+}$ 또는 $OH^{-}$의 상대적 개수($n$)를, ~~`처럼 작성한다. 이후 표·그림·자료 안에서는 긴 변수명 대신 `$n$`만 사용한다.

[전 문항 해설 요청 사항]
- 선지별 출제의도는 짧은 경어체로 적을 것.
- 출제의도는 `~~에 대한 보기입니다.`, `~~를 묻는 보기입니다.` 형식으로 쓸 것.
- 출제의도에서 `능력에 대한`, `능력을 묻는`, `지엽형`, `계산형`과 같은 표현을 사용하지 말 것.
- 전체 해설과 선지별 해설은 `~이다`, `~다` 체로 적고 경어체를 사용하지 말 것.
- 선지별 해설 앞에 `맞다`, `틀리다`를 쓰지 말 것.
- 맞는 선지만 `[풀이 및 정답 해설]` 아래에 모아 적을 것.
- 틀린 선지만 `[오답 해설]` 아래에 모아 적을 것.
- 해설 작성 시에는 선지별 해설을 우선하고, 같은 내용을 반복하게 되는 전체 해설은 생략할 것.
- 전체 해설은 ㄱ, ㄴ, ㄷ 세 선지를 판단하는 데 모두 필요한 공통 개념, 공통 계산 또는 공통 자료 해석이 있을 때만 `[풀이 및 정답 해설]` 바로 아래에 적을 것.
- 한두 선지에만 필요한 내용은 전체 해설에 넣지 말고 해당 선지별 해설에 직접 적을 것.
- 전체 해설은 선지별 정오 판정을 반복하는 구역이 아니라 세 선지의 공통 풀이를 제공하는 구역으로 사용할 것. 선지별 해설은 이 공통 풀이를 바탕으로 각 선지의 판단을 적을 것.
- 전체 해설에서 특정 선지의 판단 근거를 이미 완전히 설명했다면 해당 선지별 해설에는 같은 내용을 다시 쓰지 말고 `ㄱ. [풀이] 참조`와 같이 적을 것.
- 전체 해설에서 특정 선지의 판단 근거를 일부만 설명했다면 선지별 해설에는 공통 내용을 반복하지 말고 그 선지에 추가로 필요한 판단만 적을 것.
- 전체 해설이 없으면 별도 내용을 만들지 말고 곧바로 선지별 해설을 시작할 것.
- `[전체 해설]`이라는 별도 구역 제목을 만들지 말 것.
- ㄱ, ㄴ, ㄷ은 각각 한 번만 해설하고, 직접 해설하지 않는 선지는 `[풀이] 참조`로 처리할 것.
- 정답은 `[정답]` 구역이 아니라 `정답 : ③ (ㄱ, ㄷ)` 한 줄로 적고, 번호 뒤 괄호에 실제 정답 내용을 함께 적을 것.

전체 해설을 사용하는 경우의 중복 방지 예시는 다음과 같다.

```text
[풀이 및 정답 해설]

ㄱ, ㄴ, ㄷ을 판단하는 데 공통으로 필요한 자료 해석이나 계산을 적는다.

ㄱ. [풀이] 참조

ㄷ. 공통 풀이를 바탕으로 이 선지에만 필요한 추가 판단을 적는다.

[오답 해설]

ㄴ. [풀이] 참조
```

위 예시처럼 전체 해설과 선지별 해설에 같은 문장을 되풀이하지 않는다. 공통 풀이가 세 선지 모두에 필요하지 않다면 전체 해설을 생략하고 ㄱ, ㄴ, ㄷ의 선지별 해설만 적는다.
- `[개념출처]`에는 사용자가 요청한 대단원과 중단원을 넣을 것.
- 사용자가 입력한 대단원에 따른 대단원명은 다음 규칙을 적용할 것.
  - `통합과학 1권 1단원` → `과학의 기초`
  - `통합과학 1권 2단원` → `물질과 규칙성`
  - `통합과학 1권 3단원` → `시스템과 상호작용`
  - `통합과학 2권 4단원` → `변화와 다양성`
  - `통합과학 2권 5단원` → `환경과 에너지`
  - `통합과학 2권 6단원` → `과학과 미래 사회`
- `[개념출처]`의 문장은 `이 문항은 (대단원명) 단원 중 (중단원)에 대한 문항입니다.` 형식으로 작성할 것.

[답변에만 표시할 범위 검증 규칙]
- 문항을 생성한 뒤 교과서 범위 검증을 수행하여 사용자에게 보여줄 것.
- 논문이나 외부 연구 자료를 사용했다면 사용자가 지정한 단원별 교과서 대조를 포함한 논문 범위 검증도 사용자에게 보여줄 것.
- 검증에서는 각 ㄱ/ㄴ/ㄷ 선지가 허용 범위에 있는지 확인할 것.
- 금지 개념을 우회적으로 사용하지 않았는지 확인할 것.
- 계산에 필요한 모든 전제와 자료가 문항 안에 주어졌는지 확인할 것.
- 실제 `.md` 파일에는 다음 내용을 넣지 말 것.
  - `[교과서 범위 검증]`
  - `[논문 범위 검증]`
  - `[출제 범위 검증]`
  - 검증용 내부 추론
  - 사용자를 위한 메타 설명
- 검증 결과가 문항 수정으로 이어졌다면 수정된 최종 문항만 `.md` 파일에 넣을 것.

[논문 자료 활용 시 단원별 교과서 검증 강화]
- 사용자가 논문 자료 활용을 요청하면 논문의 과학적 신뢰성 확인과 별개로, 해당 자료가 통합과학 문항에 사용 가능한지를 사용자가 지정한 대단원·중단원·세부 내용별로 교과서와 대조하여 검증할 것.
- 논문 자체를 출제 범위의 근거로 삼지 않는다. 출제 가능성의 최종 근거는 소스에 첨부된 통합과학 교과서의 해당 단원이다.
- 논문에서 가져올 내용을 `현상과 상황`, `변수와 정의`, `실험·관측 방법`, `표·그래프의 수치`, `자료 사이의 관계`, `결론과 전문 용어`로 나누고 각 요소를 따로 검증할 것.
- 각 논문 요소가 사용자가 지정한 단원의 교과서 본문, 탐구 활동, 자료 해석 또는 개념 설명에서 직접 다루어지는지 확인할 것. 다른 단원의 개념을 융합한다면 관련된 각 단원에 대해 별도로 검증할 것.
- 핵심 개념과 판단 근거는 가능하면 서로 다른 출판사의 첨부 교과서 2종 이상에서 공통으로 확인할 것. 한 교과서에서만 확인되는 내용은 그 사실과 출처를 명시하고 지엽적인 핵심 선지로 사용하는 것을 우선 피할 것.
- 검증 결과는 다음 세 단계로 판정할 것.
  - `직접 사용 가능`: 해당 단원의 교과서에서 같은 개념이나 관계를 직접 확인할 수 있고, 논문 지식 없이도 판단할 수 있음.
  - `문항에서 자료로 제공하면 사용 가능`: 논문의 구체적 수치나 상황은 교과서에 없지만 문항 안에 충분히 제시되며, 정답 판단에는 교과서 개념만 필요함.
  - `사용 불가`: 논문의 전문 이론, 고급 통계, 연구 방법, 전문 용어 또는 교과서에 없는 인과 관계를 알아야 판단할 수 있음.
- `문항에서 자료로 제공하면 사용 가능`으로 판정한 요소는 필요한 정의, 조건, 단위, 비교 기준과 관계를 문항 안에 모두 제시하고, 학생이 논문 원문을 읽었거나 배경지식을 알고 있다고 가정하지 말 것.
- 논문에서 사용한 전문 용어가 교과서 용어와 다르면 교과서 용어로 바꾸거나 문항 안에서 뜻을 명시할 것. 뜻을 주어도 해결 과정이 교과서 범위를 벗어나면 사용하지 말 것.
- 논문 그림이나 표를 단순화하여 사용할 때는 과학적 관계를 바꾸지 말고, 교과서에서 다루지 않는 변인·통계량·해석은 제거하거나 필요한 정보를 문항에 직접 제공할 것.
- ㄱ, ㄴ, ㄷ 각각에 대해 `사용한 논문 요소`, `대응 교과서 단원`, `교과서 근거`, `출제 가능 판정`, `필요한 수정 또는 제한`을 확인할 것.
- 답변의 논문 범위 검증에는 다음 형식의 단원별 검증표를 제시할 것. 이 표와 검증 내용은 실제 문항 `.md` 파일에는 넣지 않는다.

```markdown
| 검증 대상 | 논문에서 가져온 요소 | 대응 교과서 단원 | 교과서 근거 | 판정 | 문항 반영 방식 |
|---|---|---|---|---|---|
| 자료 | 내용 | 대단원·중단원 | 출판사·교과서·해당 쪽 또는 절 | 직접 사용 가능/자료로 제공하면 사용 가능/사용 불가 | 반영·수정·제외 |
| ㄱ | 내용 | 대단원·중단원 | 출판사·교과서·해당 쪽 또는 절 | 판정 | 반영 방식 |
| ㄴ | 내용 | 대단원·중단원 | 출판사·교과서·해당 쪽 또는 절 | 판정 | 반영 방식 |
| ㄷ | 내용 | 대단원·중단원 | 출판사·교과서·해당 쪽 또는 절 | 판정 | 반영 방식 |
```

- 논문 자료가 과학적으로 타당하더라도 단원별 교과서 검증에서 `사용 불가`로 판정되면 문항에서 제외하거나 교과서 범위의 다른 자료로 교체할 것.
- 교과서 근거를 찾지 못한 상태에서 논문 내용만으로 출제 가능하다고 판정하지 말 것.

[세부내용별 문항 범위 검증 for remind]
- 산화와 환원 또는 중화 반응 문제 출제 시 아보가드로수와 mol의 개념은 사용할 수 없음.
- 중력장 내의 운동, 충격량과 운동량, 발전 문제 출제 시 운동 에너지와 퍼텐셜 에너지의 식은 사용할 수 없음.
- 판구조론과 지각 변동 문제 출제 시 고지자기의 직접적인 개념은 출제할 수 없음.
- 판의 이동 속도 문항을 출제할 때는 벡터 성분 계산이나 합성을 물을 수 없음. 같은 수직선상에서 동서 또는 남북으로 이동하는 방향에 대해서만 속도 벡터 계산을 시킬 수 있음.
- 대기와 해양의 상호작용 문제 출제 시 라니냐 개념은 사용할 수 없음. 엘니뇨는 평년과만 비교함.
- 지질 시대의 환경과 생물 문제 출제 시 지층의 절대 연령 개념은 직접적으로 사용할 수 없음. 문제에서 설명하거나 간접적으로 출제해야 함.
- 별의 진화 문제 출제 시 초기 질량과 수소 핵융합 지속 시간 간의 관계는 직접적으로 사용할 수 없음.

[맞춤법 유의사항]
아래 맞춤법 유의사항을 지킬 것. 화살표 앞은 흔히 생성되는 표현이고 화살표 뒤가 이 문항 제작에서 사용할 표현이다.

- 지구 시스템 → 지구시스템
- 이산화탄소 → 이산화 탄소
- 수산화나트륨 → 수산화 나트륨
- 전자껍질 → 전자 껍질
- 탄산칼슘 → 탄산 칼슘
- `R은` → `R가` (평가원에서 R은 아르로 읽음)

[최종 출력 전 자체 점검]
각 문항을 출력하기 전에 다음을 확인한다.

1. 실제 `.md` 파일 첫 줄에 `#` 제목이 없는가.
2. `## 문항`, `## 해설`, `### 표`가 없는가.
3. `**1.**`, `**[2.5점]**` 같은 Markdown bold가 없는가.
4. 문항과 해설 사이에 `---`가 없는가.
5. 정답이 정확히 `정답 : ③ (ㄱ, ㄷ)` 형식의 한 줄인가.
6. `[정답]` 구역이 남아 있지 않은가.
7. 해설 구역 이름이 `[출제의도]`, `[개념출처]`, `[풀이 및 정답 해설]`, `[오답 해설]`로 정확한가.
8. 수식 내부에 `\_`가 아니라 `_`가 사용되었는가.
9. 아래첨자와 위첨자에 중괄호를 사용했으며, 특히 숫자 아래첨자를 `$T_1$`이 아니라 `$T_{1}$`로 적었는가.
10. Unicode 분수·위첨자·아래첨자를 사용하지 않았는가.
11. Markdown 표의 열 수와 구분 행 열 수가 일치하는가.
12. 선택지 ①~⑤가 각각 한 줄에 하나씩 있는가.
13. 탐구/실험형 구역 이름이 정확하고 목표가 없을 때 목표 구역을 만들지 않았는가.
14. 교과서/논문 범위 검증과 그림 프롬프트가 `.md` 파일에서 제외되었는가.
15. 미리보기 코드 블록의 내용과 실제 `.md` 파일의 내용이 동일한가.
16. 문제 발문 문장 중간에 수동 줄바꿈이 들어가 있지 않은가.
17. 5글자를 초과하는 변수명 또는 물리량 설명을 발문에서 특정 문자로 정의하고 자료 안에서는 해당 문자로 치환했는가.
18. `[개념출처]`가 지정된 대단원명과 사용자가 요청한 중단원을 사용하여 `이 문항은 (대단원명) 단원 중 (중단원)에 대한 문항입니다.` 형식으로 작성되었는가.
19. 동일한 문자·변수·기호의 이탤릭체와 비이탤릭체 서식이 문제와 해설 전체에서 일관적인가.
20. 판의 이동 속도 계산에 벡터 성분 계산이나 합성을 사용하지 않았으며, 같은 수직선상의 동서 또는 남북 방향 계산만 사용했는가.
21. 탐구/실험형 문항의 문제 발문이 두 문장 이하이며, 추가 조건이나 절차가 탐구/실험 과정의 별도 단계로 옮겨졌는가.
22. 탐구/실험 과정이 3개 이상이고 시간 순서대로 제시되며, 한 과정에 여러 절차가 과도하게 묶이지 않았는가.
23. `$A$ ~ $D$는 각각 ... 중 하나이다.`처럼 서로 다름이 내포된 표현 뒤에 `서로 다르다`를 중복하여 적지 않았는가.
24. 그림 1개라면 독립 line `그림`이 정확히 존재하는가.
25. 표 1개라면 standalone `표`를 만들지 않았는가.
26. 그림+표라면 `그림 → Markdown table` 순서인가.
27. 표+그림이라면 `Markdown table → 그림` 순서인가.
28. 그림 2개라면 `그림 (가)`, `그림 (나)`를 사용했는가.
29. 표 2개일 때만 `표 (가)`, `표 (나)`를 사용했는가.
30. `그림 삽입`, `[그림 자리]`, `[이미지 자리]`, `이미지`, standalone `표` 같은 비표준 marker가 없는가.
31. 발문 안의 `그림은`, `표는`을 추가 visual item으로 중복 계산하지 않았는가.
32. 발문의 자료 순서와 실제 `.md`의 visual 순서가 동일한가.
33. 시각자료가 3개 이상 필요할 경우 최대 2개 visual item으로 합성했는가.
34. 탐구/실험 결과의 Markdown table 앞에 standalone `표`를 추가하지 않았는가.
